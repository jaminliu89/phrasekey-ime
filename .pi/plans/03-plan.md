## 证伪表

> **记录「排除了什么」比记录「做了什么」更值钱** —— 防止重复排查。
> 结论被推翻时不要删掉旧结论，改标「已证伪 + 证伪方式」。

| 猜想 | 证伪方式（用什么对照实验） | 结论 |
|---|---|---|
| 排序质量只是「好不好用」，不是「能不能用」 | 同一输入连跑 3 次，「我们」落第 6/1/3 位 | **已证伪** — 排名随机属不能用级别 |
| 「中国人」查不到是引擎 bug | `awk` 查 dict.tsv 确认无此词条 | **已证伪** — 是词库覆盖问题 |
| 音形只是「还没做完」 | 读 flypy EULA + openfly 授权结构 | **已证伪** — 是法律上不可内置，非工作量问题 |
| 双拼与全拼共用一套 progressive 逻辑即可 | 逐键模拟 `womfzd`，奇数位全空 | **已证伪** — 双拼定长 2 键需独立回退链 |
| `FlypyCodec` encode/decode 是可逆的 | 全量 417 音节往返扫描，403 通过 | **已证伪** — `wo→wuo` 等 14 项不可逆，修后 410 |
| 手写双拼码可用于测试 | `wourfg` 解码为 `wuo/shuan/f`，真码是 `womfzd` | **已证伪** — 必须用 `encode` 反推 |
| iOS 与 macOS 默认方案一致 | 读 `KeyboardViewController:62` 硬编码 `.pinyin` | **已证伪** — 已修（7c49895） |
| 只有 iOS 键盘存在默认值写死问题 | grep 默认参数，发现 `HotwordsStore.search` 默认 `.pinyin` | **已证伪** — 同源问题有第二处，待修 |
| 「常用语优先」是通用刚需 | 扫 5 个高星同类项目，无一以此为核心卖点 | **未定性** — 需求小还是难做未知；(a) 定位下不阻塞 |

### 2026-08-23 补做启动门禁

**背景**：项目已有 28 次提交，但从未有调研 / 定位 / PRD 文档。
用户质询「为什么开始产品时没做 PRD 和定位」——事实确认：确实没做，且此前
让做的同行标杆调研也未落盘（全盘搜索无任何输入法调研文档）。

**已验证的代价**（非抽象损失）：
- 约 10 次提交是 iOS 键盘反复救火，根因是未先查平台限制（Info.plist 必需键等）
- README 宣称音形为核心 feature，实际码表不存在、功能恒空转
- iOS 硬编码全拼 vs macOS 默认双拼，两端不一致数月无人发现
- 回归全测全拼而默认是双拼 → 默认路径全线断档
- 调排序先靠感觉改权重，写了探针才发现真问题是「随机」不是「不准」

**产出**：
- 新建 skill `project-inception-gate`（四端已同步）+ 可执行门禁 `inception-check.sh`
- AGENTS.md 新增工作纪律第 0 条：调研未落盘禁止写业务代码
- 本项目补齐 00-research / 01-positioning / 02-prd / 03-plan 四份文档

**调研关键结论（已验证，附证据）**：
小鹤音形官方码表闭源，EULA 第 2 条禁反向工程、第 3 条著作权全归官方；
最成熟开源复刻 openfly 作者声明「已放弃小鹤音形」转投星空键道；
4 个高星同类项目用了 4 种不同 license，全在处理同一份闭源码表的版权
→ 授权是该领域**行业级门槛**，非本项目独有困难。

**自身失误记录**：首次派 3 个 scout 并行全网调研，单个 timeout 900s
**全部超时、产出全丢**；改为自己直查 GitHub API + EULA 原文，5 分钟见效。
教训已固化进 skill（先直查一击定生死项，再考虑外包）。
