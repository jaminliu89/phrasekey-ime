## 目标用户

**唯一用户：kimliu（我自己）。**

- 是谁：小鹤双拼使用者，macOS 为主 + iOS 辅助，日常大量输入固定文本片段
  （常用语：邮箱、地址、项目路径、话术模板、代码片段）
- 现在怎么解决这个问题：主流输入法的自定义短语功能（藏得深、跨端不同步、
  数据握在厂商手里）+ macOS 系统文本替换（触发方式与输入法候选割裂）
- 为此付出什么代价：重复手打长文本；换设备要重新配；数据格式不透明无法批量管理

> **不为任何其他用户设计。** 这是本轮定位最重要的收敛 ——
> 项目性质选 (a) 自用工具，因此「别人会不会用」不是判据。

## 为什么换过来

- **唯一核心差异**：**常用语与拼音候选在同一个候选条里，打拼音缩写就能直接上屏长文本，
  且数据是本地开放格式（TSV/JSON）我能自己批量改。**

  拆开说，它同时要求三件事成立，缺一个就不成立：
  ① 常用语命中时**置顶**（不需要额外按键、额外面板、额外前缀符号）
  ② 默认走**小鹤双拼**（我的肌肉记忆）
  ③ 数据在我自己的目录里，可 git、可脚本批处理

- 这个差异是真痛点吗，证据是：
  **部分验证。** 我确实每天重复手打长文本（真实行为，非假设）。
  但「现有方案到底差在哪」尚未逐个实测 —— 见 00-research.md 待办。
  → 标记为 **猜想（强）**，不是已验证事实。

- 竞品为什么没做：
  调研发现 **5 个高星同类项目没有一个以常用语为核心卖点**（00-research.md §3）。
  尚未定性是「需求小」还是「难做」（Unknown 高）。
  → 但在 (a) 自用工具定位下，**这个问题不阻塞** —— 我一个人的需求成立就够了。
  → 若未来转 (b)/(c)，必须先回答这个问题。

## 明确不做（≥5 条）

选定 (a) 自用工具后，以下全部砍掉或降级。**这是本次定位最大的产出 —— 砍掉虚功。**

1. **不做 Windows / Linux 移植** —— 我不在这两个平台上打中文；README 路线图的
   「TSF/ibus (planned)」属于给想象中的用户画的饼，直接删。
2. **不做对外推广 / 争取用户 / 上架 App Store** —— 没有用户就没有兼容性包袱、
   没有 App Store 审核约束、不需要 onboarding 引导。
3. **不内置小鹤音形官方码表** —— EULA 明文禁止反向工程、著作权全归官方
   （00-research.md §1 已验证）。自用场景下我自己装一次码表即可，零成本。
4. **不做剪贴板历史** —— README 路线图里的未勾选项。与核心链路无关，
   且已有专门工具解决；`clipboardHistory` 配置项保留但不实现。
5. **不做云同步 / 账号体系** —— 数据放我自己的目录 + git 即可，
   这本身就是「数据不锁定」的实现方式，不需要造服务端。
6. **不做多用户 / 权限 / 隐私合规文案** —— 单人使用，无此需求。
7. **不追求候选质量对标商业输入法** —— 20 万词库 + 覆盖度排序够我日常用；
   不做用户行为大数据调优。
8. **不做插件系统 / 主题系统** —— 过度设计，我不需要换皮。

## 项目性质（必选一项，直接决定投入强度）

- [x] **自用工具** —— 砍掉对外宣传与跨平台路线图，只保证自己的主链路好用
- [ ] 开源要有人用
- [ ] 未来商业化

选定理由：

**iOS 键盘长时存活、真机内存、App Group 常用语落盘这三件核心事至今没在真机验过。**
连「我自己能不能日常用」都还没证实，谈推广和商业化是虚的。

选 (a) 的直接收益：
- 砍掉 8 类工作（见上），把精力全押在「主链路真机可用」
- 音形授权问题从「阻塞」降级为「非问题」（自己装码表即可）
- 「常用语是不是真需求」这个 Unknown 从「阻塞定位」降级为「不阻塞」
- 仓库仍保持 MIT 开源（放着给人看没成本），但**不承担维护承诺**

> ⚠️ 若未来要转 (b) 开源要有人用，必须重做本文件，并先回答：

## 成功判据

怎么算这个项目成功了（可量化，可验证）。

- **主判据**：连续 7 天用它作为唯一输入法完成日常输入（macOS），不出现
  「切回系统输入法才能打完」的情况
- iOS 键盘连续使用 1 小时不被系统杀掉
- 常用语在 macOS 与 iOS 两端都能命中并置顶（App Group 数据互通）
- 默认小鹤双拼路径 0 断档（已固化为回归，见 03-plan.md）
- 同输入的候选顺序稳定可预测（已修，排序全序化）

## 失败判据 / 退出条件

什么情况下应该停掉或转向。

- iOS 键盘经多轮修复仍无法稳定存活 → **放弃 iOS 端，退化为纯 macOS 工具**
  （iOS 已耗掉约 10 次救火提交，止损线要明确）
- macOS 端连续 7 天试用中出现无法忍受的候选质量问题且排序调优无效
  → 考虑改为 RIME 方案 + custom_phrase 配置，放弃自研引擎
- 维护成本超过它省下的时间 → 归档
