# PhraseKey 产品走查（架构师 / PM 视角）

> 2026-08-24。触发：用户报「不能多字连打」，并要求「把让你做的优点逻辑引擎都拿来，把产品走查完」。
> 本文是**决策依据**：定清动什么、不动什么、按什么顺序动。

---

## 0. 一句话结论

**引擎缺一个架构级能力：整句切分（sentence segmentation）。**
现有实现只会「拿整串去查词典」，词典里没有这个组合就退化成最长前缀 ——
所以用户连打 `wouivsgo`（我是中国）只得到「我是」，后半截 `vsgo` 被静默丢弃。

这不是 bug，是**从未实现的功能**。而它恰好是我在 `00-research.md` §7
调研 McBopomofo 时记为「第一条技术点」的东西 —— 调研了没落地。

---

## 1. 现状实测（证据）

| 输入 | 期望 | 实得 | 判定 |
|---|---|---|---|
| `woui` | 我是 | 我是 | ✅ 单词可用 |
| `wouivsgo` | 我是中国 | **我是**（`vsgo` 丢弃） | ❌ 多字连打断裂 |
| `nihcwomf` | 你好我们 | **你好**（`womf` 丢弃） | ❌ |
| `vidcwoyao` | 知道我要 | **知道**（`woyao` 丢弃） | ❌ |
| `wouiyigxug` | 我是一个学生 | **我是** | ❌ |

规律：**只输出第一个能命中词典的词，其余全部丢弃且无提示。**

用户的实际使用姿势是「一口气打一句，空格上屏」——
这是所有成熟输入法的默认交互，而本项目做不到。

## 2. 为什么现在才暴露

此前所有测试用例都是**单个词**（`nihc` / `womf` / `ojqr`），
68 条断言全绿，但没有一条测「两个词连着打」。

→ 与前几轮同一个病根：**测试用例的形状决定了能发现什么 bug。**
  按「词」设计用例，就永远发现不了「句」的问题。
  已在零声母那轮记过一次（按规则维度 vs 按常用词），这次是按**输入长度维度**的盲区。

---

## 3. 该拿的机制（调研已记录但未落地）

| 来源 | 机制 | 为什么必须拿 | 优先级 |
|---|---|---|---|
| McBopomofo §7① | **DAG 最短路径整句切分**（`walk()`） | 直接解决多字连打，是本次核心 | **P0** |
| McBopomofo §7③ | 词频取对数 + 长词加权 `fscale=2.7` | 切分时需要「长词优于多个短词」的打分，否则「我是中国」会被切成 4 个单字 | **P0**（P0 的必要组件） |
| McBopomofo §7② | 用户词分数 = `topScore + epsilon` | 防止单字用户词压死多音节词；本项目自学习与切分交互时必然撞上 | P1 |
| 搜狗 §6 | 短语带排序号字段 | 常用语可版本化管理 | P2 |
| Hamster §8 | 候选栏分页 / 长按删词 | 交互优化，非阻塞 | P2 |

**结论：P0 是「整句切分 + 长词加权打分」，这两个必须一起做**（只做切分不做打分，会切出一堆单字）。

## 4. 架构决策：怎么加而不破坏现有优点

### 硬约束（用户明确要求「逻辑不变保持现在的优点」）

现有已验证可用、**不得回退**的能力：

| 能力 | 实测证据 | 保护方式 |
|---|---|---|
| 双拼全码精确命中首选 | 12/12 | 切分**仅在整串查不到时**才启动 |
| 零声母 o 引导 | 12/12 + 组词 8/8 | 切分复用 `FlypyCodec`，不重写解码 |
| 日常口语搭配 | 14/14 | 同上，词典不变 |
| 常用语置顶 | 已有断言 | 切分结果排在常用语**之后** |
| 分隔符 `'` | 6/6 + 等价性 6 | 在 `Searcher` 层已剥离，切分看不到它 |
| 查询 0.164ms | bench | 切分有 O(n²) 风险 → 必须设长度上限并实测 |

### 选定方案：**旁路增强（bypass）**，不改主路径

```
query(input, scheme)
  ├─ 常用语命中        → 原样返回（不变）
  ├─ 整串精确命中      → 原样返回（不变）★ 保护 12/12
  └─ 都没命中时         → 新增：整句切分
                          ├─ 切分成功 → 返回拼接词
                          └─ 切分失败 → 落回原有渐进兜底（不变）
```

**关键设计**：切分是**最后一道**，插在「原有兜底」之前。
这样任何现在能打出来的东西，路径完全不变 —— 风险被限制在「现在打不出来」的输入上。

### 明确不做（避免过度工程）

- ❌ **不做整句连续输入的 UI**（边打边显示已选定的词）—— 改动面太大，先让候选出得来
- ❌ **不换引擎**（librime）—— 已在 §8 论证
- ❌ **不做 N-gram 语言模型** —— McBopomofo 用的是 unigram + 长词加权，够用；
  N-gram 需要语料训练，超出自用工具范围

## 5. 验收标准（可量化，写死为回归）

| 项 | 标准 |
|---|---|
| 多字连打 | `wouivsgo`→我是中国、`nihcwomf`→你好我们 等 ≥8 例首选正确 |
| **不回退** | 现有 80 条断言**全部继续通过**（这是硬门禁） |
| 性能 | 单次查询仍 < 0.5ms；长串（12 键）切分 < 2ms |
| 长度上限 | 超过 N 键不做切分（防 O(n²) 卡顿），N 由实测定 |

---

## 6. 执行顺序

1. 先写**不回退回归**（现有能力全锁死），再动代码 —— 防止改出退化不自知
2. 实现切分 + 长词加权打分
3. 实测性能，定长度上限
4. 装机交付用户
