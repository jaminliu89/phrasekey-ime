## 一、版本目标

**解决"能用但难用"的核心体验问题，让一个老双拼用户愿意每天用。**

- 核心交互 0 摩擦：分词号选二候选、标点符号直接上屏不卡、常用语一键展开
- 视觉达到 Gboard 80% 的干净程度

### v1.0 目标

**从"自己能用的输入法"到"可以推荐给朋友的输入法"。**

成功指标：
- 新用户开箱 5 分钟内可以流畅打字（不用查文档）
- 常用语功能完整（导入/管理/触发/展开）
- Mac + iOS 双端体验一致

## 三、功能详细规格

### 3.1 双拼分号选词（P0）

#### 交互逻辑
- 双拼模式下，当存在正在输入的拼音串且候选数 ≥ 2 时：
  - 按 `;`（分号）→ 选候选第 2 位（索引 1），上屏并清空拼音
  - 按 `'`（引号）→ 选候选第 3 位（索引 2），上屏并清空拼音
- 没有正在输入的拼音时：
  - `;` 和 `'` 直接上屏（和普通符号键一样）
- 候选不足时：
  - 只有 1 个候选时，`;` 直接上屏分号
  - 只有 2 个候选时，`'` 直接上屏引号
- 全拼模式下：默认关闭（可在设置里开启）

#### 设计依据
- 小鹤音形等双输入法的标准交互
- 双拼用户双手盲打，分号键在右手小指位置，不需要移动手去按顶部数字键
- 数字键 1/2/3 仍然可用（兼容全拼用户习惯）

#### 边界情况
- 候选只有常用语时：同样适用
- 翻页后：`;` 选当前可视窗口的第 2 位
- 选中态为第 1 位时按 `;`：直接上屏第 2 位（不是移动选中项）

### 3.2 候选栏视觉规范（P0）

#### 设计原则
- 只用字重 + 灰度区分层级，不用彩色
- 选中态用浅灰底 + 加字重，不改文字颜色
- 圆角、留白、间距对齐 Gboard

| 序号数字 | #999999（浅灰） | Semibold | 11px |
| 序号数字（选中） | #666666（中灰） | Semibold | 11px |

#### 布局规范

- 位置：候选栏左侧（Mac）或顶部单独一行（iOS）
- 颜色：与候选文字同色
- 字重：Regular
- 字号：比候选字小 2px
- **不使用蓝色**——拼音是输入状态的反馈，不是可交互元素，不需要用颜色强调

### 3.3 常用语自动展开（P1）

#### 交互逻辑
1. 用户输入常用语的 key（如 `addr`）
2. 引擎检测到 key 精确匹配常用语
3. 按触发键（默认空格）时：
   - 删除已输入的 key
   - 插入完整的常用语文本
   - 清空拼音输入状态
4. 如果用户想选其他候选（不是展开）：
   - 按数字键 1/2/3 等 → 正常选词，不展开
   - 按 Esc → 取消输入

#### 配置项
```json
{
  "autoExpandHotwords": true,
  "autoExpandTrigger": "space",
  "autoExpandKeepTrigger": false
}
```

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| autoExpandHotwords | 是否启用自动展开 | true |
| autoExpandTrigger | 触发键：space / enter / tab / custom | space |
| autoExpandKeepTrigger | 展开后是否保留触发字符 | false |

#### 与候选栏显示的关系
- 自动展开开启时，常用语仍然出现在候选栏第 1 位（带 ⌘ 标记）
- 只是按空格时直接展开，不需要按 1
- 用户按其他数字键仍然可以选别的候选

### 3.4 常用语管理面板（P1）

#### Mac 端（PhrasesPanel）
- 入口：菜单栏图标 → "常用语"，或快捷键 ⌘⇧P
- 布局：左侧列表 + 右侧详情
- 列表显示：key（左对齐，monospace 字体）+ text 预览（右对齐，灰字）
- 搜索框在顶部，实时过滤
- 底部：+ / - 按钮 + 导入/导出
- 双击某条常用语 → 直接插入到当前前台 App

#### iOS 端（宿主 App）
- 底部 Tab：常用语 / 设置
- 常用语列表：key 在上（小字灰字），text 在下（正文字）
- 右上角 + 号添加
- 左滑删除
- 搜索框在顶部
- 设置里有导入/导出（通过文件 App）

#### 数据格式
```json
[
  {
    "hw_id": "uuid-string",
    "key": "addr",
    "text": "北京市朝阳区建国路88号SOHO现代城A座1001室 100022",
    "created_at": 1690000000,
    "usage_count": 15
  }
]
```

### 3.5 自学习机制（P1）

#### 学习规则
- 用户每次手动选择一个候选（不是自动上屏的首选），该词的 freq +1
- 学习数据存在 `learned_dict.tsv`
- 用户词典 freq 权重 = 基础词频 × 1000（确保自学习词排在前面）
- Debounce：3 秒内多次学习合并写盘

#### 数据格式
```
pinyin\tword\tfrequency
ni hao\t你好\t3
```

#### 清空与导出
- 设置里有"清空学习数据"按钮
- 学习数据可以随用户词典一起导出

## 四、非功能需求

### 性能
- 候选响应时间：按键按下 → 候选刷新 < 16ms（60fps）
- 冷启动时间（Mac）：从点击输入框到键盘可用 < 100ms
- 冷启动时间（iOS 键盘扩展）：< 300ms（首帧可交互）
- 内存占用（iOS 键盘扩展）：< 30MB（留出系统预算余量）
- 词库加载时间（3 万条）：< 500ms

### 稳定性
- 连续使用 1 小时不崩溃
- iOS 键盘扩展不会被系统惩罚性卸载
- 异常情况下（词库损坏、数据目录不可写）优雅降级，不闪退

### 隐私
- 不联网、不上传任何数据
- 不收集使用统计
- 不读取剪贴板（除非用户主动触发粘贴）
- RequestsOpenAccess = false（iOS 端不需要完全访问）

### 兼容性
- macOS：13.0 Ventura 及以上
- iOS：16.0 及以上
- 数据格式向前兼容（旧版本数据文件新版本能读）

## 五、待决策项

1. **全拼模式下分号选词要不要默认开启？**
   - 倾向：默认关闭，可在设置里开（全拼用户更习惯按数字键）
2. **常用语展开的默认触发键是空格还是 Tab？**
   - 倾向：空格（TextExpander 也是空格，用户习惯一致）
3. **iOS 端键盘高度要不要可调节？**
   - 倾向：先固定高度，后期加设置（固定高度 bug 少、适配简单）
4. **要不要做系统 Text Replacement 同步？**
   - 倾向：不做（私有 API 有被拒风险，而且系统的已经够用了）
